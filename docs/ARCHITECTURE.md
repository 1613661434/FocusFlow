# FocusFlow 系统架构

## 1. 总体结构

```text
┌──────────────────────────────────────────────────────────┐
│ Qt Widgets 视图层                                       │
│ Dashboard / Task / Project / Focus / Statistics / Settings│
└──────────────────────────┬───────────────────────────────┘
                           │ Signals / Slots 与方法调用
┌──────────────────────────▼───────────────────────────────┐
│ 业务服务层                                               │
│ FocusTimer / PriorityService / NotificationSoundPlayer   │
│ DataManagementService                                    │
└──────────────────────────┬───────────────────────────────┘
                           │
┌──────────────────────────▼───────────────────────────────┐
│ Repository 数据访问层                                   │
│ Task / Project / Focus / Settings / Analytics Repository │
└──────────────────────────┬───────────────────────────────┘
                           │ Qt SQL
┌──────────────────────────▼───────────────────────────────┐
│ SQLite：任务、项目、分类、专注记录、预设与设置           │
└──────────────────────────────────────────────────────────┘
```

视图不直接负责复杂业务规则。任务推荐、倒计时、声音播放和备份分别由独立服务
封装；普通查询和写入由 Repository 完成。这样的划分便于单元测试，也便于在
报告中说明系统的高内聚、低耦合设计。

## 2. 关键模块

### 2.1 FocusTimer 状态机

计时器包含三种阶段：专注、短休息、长休息；每个阶段又包含空闲、运行、暂停
三种状态。剩余时间依据实际经过的墙上时钟时间计算，而不是简单假设每次
`QTimer` 回调都正好间隔一秒，因此界面卡顿或系统调度延迟不会累计计时误差。

### 2.2 PriorityService 推荐规则

推荐分数由以下因素叠加：

- 重要程度越高，基础分越高。
- 已逾期或接近截止时间时增加紧迫度分数。
- 预计耗时较短时给予少量“快速完成”加分。
- 已进入进行中的任务获得连续性加分。

页面同时展示分数和推荐原因，使规则结果可以解释，答辩时也容易演示和验证。

### 2.3 通知与自定义声音

`QSystemTrayIcon` 负责最小化驻留和桌面消息；`QMediaPlayer` 与
`QAudioOutput` 负责音频解码和音量。服务层用独立停止计时器限制单次播放
长度，并控制重复次数。没有配置音频或解码失败时可回退到系统提示音。

### 2.4 数据安全

SQLite 运行在 WAL 模式。备份使用 SQLite 的 `VACUUM INTO` 生成一致、独立
的数据库文件，避免只复制主文件而遗漏 WAL 中的数据。恢复前执行 SQLite
`quick_check` 并检查 FocusFlow 必需表；随后自动备份当前数据，将待恢复文件
暂存到应用目录，下次启动且数据库尚未打开时再替换。

CSV 通过 `QSaveFile` 原子写入，使用 UTF-8 BOM 方便中文 Windows 表格软件
识别编码，并对逗号、双引号和换行进行标准 CSV 转义。

## 3. 数据库表

| 表 | 作用 | 关键关系 |
|---|---|---|
| `tasks` | 任务主体、状态、重要度、截止和预计时间 | 可关联项目与分类 |
| `projects` | 长期目标或上下文 | 归档不删除已有任务 |
| `categories` | 跨项目分类及颜色 | 删除后任务分类置空 |
| `focus_sessions` | 专注/休息的计划与实际时长 | 可关联任务 |
| `timer_presets` | 专注和休息周期预设 | 保存默认番茄钟 |
| `settings` | 键值形式的个人设置 | 声音、自动切换等 |

外键删除采用 `SET NULL`，即便项目、分类或任务发生变化，历史专注数据也不会
因为父对象删除而丢失。

## 4. 页面刷新机制

- 任务发生变化时，任务页发出 `tasksChanged`，仪表盘、统计页和计时任务列表刷新。
- 项目或分类变化时，任务页刷新可选项和列表展示。
- 专注记录保存后，仪表盘与统计页刷新。
- 设置保存后，计时页面重新载入计时和声音参数。

该机制使用 Qt Signals/Slots，让页面之间不直接持有彼此的业务状态。

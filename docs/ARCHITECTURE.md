# FocusFlow 系统架构

本文档描述 FocusFlow v0.1.35 的代码结构、关键流程和主要设计取舍。

## 1. 总体分层

```text
┌─────────────────────────────────────────────────────────────┐
│ 应用协调层                                                  │
│ main / SingleInstanceGuard / MainWindow                     │
└────────────────────────────┬────────────────────────────────┘
                             │ 启动编排、Signals / Slots
┌────────────────────────────▼────────────────────────────────┐
│ Qt Widgets 视图层                                           │
│ Dashboard / Task / Project / Focus / Statistics / Settings │
│ Dialogs / 自定义控件                                        │
└────────────────────────────┬────────────────────────────────┘
                             │ 方法调用与业务事件
┌────────────────────────────▼────────────────────────────────┐
│ 服务层                                                      │
│ FocusTimer / PriorityService / NotificationSoundPlayer      │
│ SoundStorageService / DataManagementService                 │
└────────────────────────────┬────────────────────────────────┘
                             │ 领域读写
┌────────────────────────────▼────────────────────────────────┐
│ Repository 数据访问层                                      │
│ Task / Project / Focus / Settings / TimerPreset / Analytics │
└────────────────────────────┬────────────────────────────────┘
                             │ Qt SQL
┌────────────────────────────▼────────────────────────────────┐
│ SQLite：任务、项目、分类、专注记录、计时预设与设置          │
└─────────────────────────────────────────────────────────────┘
```

视图负责呈现和用户交互；可复用业务规则放入服务；SQL 访问集中在 Repository；
应用协调层处理进程生命周期、主窗口和跨页面事件。该结构使推荐算法、倒计时、
数据管理和单实例通信能够脱离具体页面进行测试。

## 2. 目录职责

| 目录 | 职责 |
|---|---|
| `src/app` | 主窗口、页面协调、托盘和单实例控制 |
| `src/views` | 六个主要页面及任务、关于等对话框 |
| `src/widgets` | 日历、滚轮保护、颜色下拉框、排序项等通用控件 |
| `src/services` | 计时、推荐、声音存储/播放和数据管理 |
| `src/repositories` | 任务、项目、专注、统计和设置数据访问 |
| `src/data` | 数据库路径、连接、建表、迁移和默认数据 |
| `src/models` | 页面与服务共享的数据结构 |
| `resources` | 应用图标、资源清单和 Windows 资源文件 |
| `tests` | Qt Test 自动化测试 |
| `tools` | 构建和 Windows 打包脚本 |

## 3. 启动与单实例流程

```text
创建 QApplication
       │
设置应用名、版本、区域和图标
       │
SingleInstanceGuard 尝试获得 QLockFile
       ├── 获得锁：清理失效端点并启动 QLocalServer
       │             │
       │             ▼
       │       初始化 SQLite → 创建并显示 MainWindow
       │
       └── 未获得锁：QLocalSocket 发送 activate
                     │
                     └── 第二进程正常退出
```

实例键由应用数据目录计算哈希，同一 Windows 用户的 FocusFlow 共用一个键。
`QLockFile` 负责判定主实例，`QLocalServer` / `QLocalSocket` 负责发送恢复请求。
实例检查发生在数据库初始化之前，因此第二进程不会再次打开 SQLite。

主窗口收到请求后：

1. 移除最小化状态，但保留原来的最大化或普通窗口状态。
2. 如果窗口已隐藏到托盘，则重新显示。
3. 调用 `raise()` 与 `activateWindow()` 将窗口带到前方。
4. 不重新创建页面，不重置筛选条件，也不影响正在运行的计时。

Windows 下第二进程还会允许主进程取得前台焦点，减少系统焦点保护导致的只闪烁
任务栏而不显示窗口的情况。

## 4. 主窗口与页面通信

`MainWindow` 创建六个页面，并用 Signals/Slots 传播变化：

- 任务变化后，概览、统计和专注关联列表刷新。
- 项目或分类变化后，任务、概览、专注和统计同步刷新名称及颜色。
- 专注记录保存后，概览和统计刷新。
- 设置保存后，专注页面重新加载计时及声音参数。
- 专注方案变更后，任务默认方案、设置页方案表和计时页选择同步刷新。
- 计时状态或剩余秒数变化后，主窗口更新托盘悬停文本。
- 概览任务被双击后，主窗口切换到专注页面并选中对应任务。
- 任务页右键菜单发出任务标识后，主窗口切换到专注页面并建立同样的任务关联。
- 切离设置页前，由主窗口协调保存、放弃或取消切换，并同步导航高亮。

页面之间传递的是业务事件或标识，不复制彼此的业务状态。
任务页在状态更新后重新读取数据、恢复排序，并显式清除行选择和当前索引。状态按钮
随之禁用，用户重新选择任务后才可再次切换状态，避免排序移动当前行造成连续误操作。
待处理任务使用“完成”，已完成任务使用“恢复”；两种文字长度一致，状态切换不会改变
按钮布局，同时工具提示和无障碍名称也与实际操作保持一致。

`FocusPage` 通过 `activeFocusTaskChanged` 把当前专注任务标识传给 `TaskPage`。
任务页将其临时渲染为紫色“进行中”并禁用状态按钮，而不向数据库写入临时状态；
这样程序意外中断后不会遗留错误的“进行中”数据。计时页刷新关联任务列表时始终保留
当前专注任务，即使其持久化状态或项目、分类在其他页面被修改。

任务页的编辑、状态和删除按钮由 `updateActionButtons()` 统一管理。选择为空或任务正在
专注计时时，三个按钮都使用 Qt 原生禁用状态；空白点击清除选区后，选择判断只读取
`selectionModel()->selectedRows()`，不依赖仍可能暂时保留的 current index。

## 5. FocusTimer 状态机

计时类型包括专注、短休息和长休息；控制状态包括空闲、运行和暂停。

```text
空闲 --开始--> 运行 --暂停--> 暂停 --继续--> 运行
  ▲              │                         │
  └----终止-------┴------自然结束-----------┘
```

计时运行时保存目标结束时间，界面刷新时用当前系统时间重新计算剩余秒数，而不是
假设每个 `QTimer` 回调都准确间隔一秒。因此最小化、系统调度延迟或短暂界面卡顿
不会持续累积误差。暂停时保存剩余时长，继续时重新建立目标结束时间。

专注记录保存计划时长、实际时长、计时类型、结果和可选任务关系。休息可保存为
历史记录，但统计查询只累计专注类型。

`TimerPresetRepository` 管理多个命名方案。任务可通过 `timer_preset_id` 绑定方案；
空值表示跟随系统默认。计时页把任务自动方案与本次临时选择分开，运行后锁定方案，
保证一条记录的计划时长不会在中途改变。`is_builtin` 标记四个内置预设，仓储层
和界面层同时阻止修改、删除，复制时则生成普通用户方案。自定义本次方案对专注、
两种休息、周期和自动衔接使用“输入值/已确认值”两级状态，只有整体确认后才更新
本次计时配置；已确认配置还可命名写入 `timer_presets`，成为普通用户方案。
方案使用独立的 `breaks_enabled` 表达是否安排休息，不把 0 分钟复用为模式标志。
无休息方案通过 `auto_start_next_focus` 决定一轮结束后停回空闲状态还是保存记录后
自动启动下一轮；普通方案继续使用两项专注/休息自动衔接字段。
保存对话框读取现有方案名称并生成最小可用默认名，基础名称视为第一项，发生重名时
从数字 2 开始递增。这样用户可以直接确认保存，同时仍可手动覆盖建议名称。

设置页的方案表为每个单元格保存独立排序键，数值列按真实数值排序。默认状态键为
默认、系统默认、系统预设、用户自定义四级；刷新数据时保留当前排序列与方向。
表格视口固定为 5 行并按需显示内部滚动条。`FocusAwareTableWidget` 只有获得焦点后
才消费滚轮事件，否则把事件交给外层设置页。获得焦点后即使滚动条到达边界也明确
接受事件，阻止滚轮继续冒泡到外层设置页。
方案表通过空白点击过滤器绑定到方案卡片、说明和设置内容区域，清除行选择与当前
索引；计时页只清除方案下拉框焦点，不改变其当前数据，避免把“取消高亮”误实现为
丢失有效计时配置。
专注页主计时卡与右侧选项卡并列；选项卡放在独立 `QScrollArea` 中，仅在可用高度
不足时出现纵向滚动，从而适配 1080p 高缩放环境而不改变宽屏、高分辨率布局。

## 6. 推荐分服务

`PriorityService` 对未完成任务计算可解释的确定性分数：

| 因素 | 分值 |
|---|---:|
| 重要程度 | `importance × 20` |
| 已逾期 | `+40 + min(逾期天数 × 3, 20)` |
| 12 小时内到期 | `+35` |
| 24 小时内到期 | `+28` |
| 72 小时内到期 | `+18` |
| 168 小时内到期 | `+8` |
| 预计 1～25 分钟 | `+5` |
| 进行中 | `+10` |

已完成或已取消任务的分数为 0。相同规则同时服务于今日概览、智能推荐筛选和
专注关联任务，避免不同页面出现排序口径不一致。颜色只用于增强分段识别，实际
排序使用数值。

## 7. 数据库设计

| 表 | 作用 | 主要关系 |
|---|---|---|
| `tasks` | 标题、描述、状态、重要度、截止和预计时间 | 可关联项目、分类和默认专注方案 |
| `projects` | 长期目标或上下文、颜色与归档状态 | 被任务引用 |
| `categories` | 跨项目分类及颜色 | 被任务引用 |
| `focus_sessions` | 专注/休息的计划与实际时长 | 可关联任务 |
| `timer_presets` | 命名方案、休息方式、自动衔接、内置标记及周期 | 任务可选关联；用户方案删除时 `SET NULL` |
| `settings` | 键值形式的个人设置 | 声音和窗口行为等 |

SQLite 使用外键约束和 WAL 模式。项目、分类或任务删除后，相关外键按
`SET NULL` 处理，历史专注记录不会级联丢失。应用通过当前对象标识读取项目和
分类颜色，因此修改颜色后，最近记录和图表会显示最新颜色。

## 8. 统计与可视化

`AnalyticsRepository` 提供：

- 今日专注、近 7 天专注和今日完成任务汇总。
- 近 7 天按日期聚合的专注秒数。
- 近 30 天按分类及项目聚合的专注占比。
- 按开始时间倒序取得最近 10 条专注记录。

统计页用 Qt Charts 绘制柱形图和饼图。柱形悬停提示由页面根据柱体几何位置计算，
只显示数字，并固定在柱顶正上方居中。饼图缩小绘图区为外侧标签留出空间，并按
相邻小扇区的角度距离递增标签引导线长度，避免同侧标签重叠。最近记录使用单独页面
切换，表格高度容纳 10 行且关闭内层滚动，以避免和外层页面滚动冲突。

## 9. 声音、托盘与窗口行为

`NotificationSoundPlayer` 保留 `QApplication::beep()` 提供的原版平台提示音作为默认；
清脆、柔和和简洁三种提示音在内存中生成 WAV 数据，自定义音频由 `QMediaPlayer`
和 `QAudioOutput` 从托管文件播放。限时模式会按播放上限动态选择淡出区间，最长约
1.8 秒；完整播放模式不启动限制计时器。新提醒到来而旧声音仍在播放时，播放器先
完成旧声音淡出，再启动待播放声音，避免重叠或硬切。

声音选择和播放方式使用 `FocusAwareComboBox`：只有控件已经获得焦点时才消费滚轮
事件，否则把事件留给外层设置页面。完整播放模式同时禁用“最长播放”标签和输入框，
通过语义状态和灰色外观明确说明该字段当前无效。

`SoundStorageService` 将用户选择的文件复制到应用数据目录。设置保存后，只保留
当前仍被专注或休息提醒引用的副本，避免不断更换声音造成磁盘占用增长。

`QSystemTrayIcon` 负责后台驻留：最小化仍显示在任务栏，关闭窗口隐藏到托盘，
托盘菜单“退出”才结束进程。`FocusPage` 组合当前任务、阶段、暂停状态与剩余秒数，
通过信号让 `MainWindow` 每秒更新托盘悬停文本。单实例恢复和托盘恢复共用同一个
窗口激活入口，保证两种方式的行为一致。

专注时间按本地时间字符串保存。统计查询直接格式化该本地时间，不再重复执行
时区转换，避免最近记录被额外偏移到未来。

## 10. 数据备份与恢复

- 备份使用 SQLite `VACUUM INTO`，生成包含 WAL 已提交内容的一致数据库。
- 恢复前执行 `quick_check` 并检查 FocusFlow 必需表。
- 当前数据库先自动备份，所选文件再复制为待恢复文件。
- 下次启动且 SQLite 尚未打开时才替换正式数据库。
- CSV 使用 `QSaveFile` 原子写入、UTF-8 BOM 和标准字段转义。
- “清空统计数据”只删除专注与休息记录，不删除任务、项目、分类或设置。

## 11. 自动化测试架构

CTest 当前注册 12 个 Qt Test 目标，覆盖：

- 单实例通知与锁生命周期
- 计时状态机和专注页面
- 多专注方案、任务绑定、删除回退和托盘状态文本
- 推荐分规则
- 数据库备份、恢复与 CSV
- 中文日历和 Qt 标准控件本地化
- 滚轮保护、任务对话框和关于对话框
- 今日概览筛选、颜色和截止时间

服务和自定义控件采用小范围目标独立编译。需要数据库的页面测试使用隔离的测试
数据，避免修改用户正式数据库。

## 12. 主要设计取舍

- **本地优先而非账号系统**：减少部署和使用门槛，同时保护个人数据。
- **规则推荐而非黑盒模型**：便于用户理解、开发者验证和长期维护，不依赖网络接口。
- **专注完成不等于任务完成**：时间投入和工作结果是两个独立事实，由用户确认任务状态。
- **关闭到托盘而非直接退出**：保证计时与提醒持续运行，同时提供可关闭的提示。
- **单实例而非多窗口**：避免重复计时状态和 SQLite 并发使用造成困惑。
- **恢复延后到下次启动**：避免在数据库连接仍打开时覆盖数据库文件。

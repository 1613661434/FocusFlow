# FocusFlow 产品路线与发布标准

本文档以 FocusFlow v0.1.35 为当前产品基线，面向用户、开发者和贡献者说明产品
定位、已交付能力、质量标准以及后续迭代方向。

## 1. 项目定义

- 中文名称：FocusFlow 个人任务规划与专注管理系统
- 英文名称：FocusFlow — Personal Task Planning and Focus Management System
- 项目类型：Windows 本地桌面效率工具
- 主要技术：C++17、Qt 6 Widgets、SQLite
- 目标用户：学生、职场人士、自由职业者以及需要管理个人事务的普通用户
- 核心目标：在同一应用中完成“规划任务、决定下一步、专注执行、安排休息、回顾投入”

系统不要求登录，不依赖云服务。任务、设置和统计数据默认只保存在用户本机，
并通过数据库备份及 CSV 导出提供可迁移能力。

### 2.2 非功能需求

- **正确性**：倒计时按实际系统时间校正，界面延迟不会长期累积误差。
- **可用性**：状态文字与颜色同时表达含义；紧凑高度可滚动；禁用字段不改变布局；纯文字菜单不预留图标空位；表格支持排序和空白处取消选择。
- **一致性**：项目、分类、重要度、推荐分和状态颜色跨页面保持一致。
- **数据安全**：删除前确认；数据库恢复前校验，并自动保护当前数据库。
- **可靠性**：同一用户只能运行一个 FocusFlow 主实例，重复启动只恢复原窗口。
- **可测试性**：计时、推荐、数据管理、控件和单实例通信均提供自动化测试。
- **可维护性**：视图、服务、数据仓库和数据库初始化分层组织。

## 3. 典型使用闭环

1. 用户建立项目和分类，并为它们设置颜色。
2. 用户创建任务，填写重要程度、截止时间和预计耗时。
3. 系统计算推荐分，在今日概览中给出下一项行动建议。
4. 用户双击建议，自动关联任务并开始专注。
5. 系统保存实际专注时长，并按设置进入短休息或长休息。
6. 用户在统计页查看趋势、时间占比和最近记录。
7. 用户定期备份数据库或导出 CSV。

重复点击桌面图标时，系统不会创建第二套业务状态，而是将原窗口恢复到前台，
因此正在进行的计时和当前页面都保持不变。

### 5.2 人工验收场景

- 新建任务后，任务页、今日概览和计时关联列表同步刷新。
- 状态按钮对待处理任务显示“完成”、对已完成任务显示“恢复”；操作后状态立即刷新并清除当前选择，排序不会造成选中行跳动，禁用按钮也无法被连续误触。
- 专注计时中的关联任务显示“进行中”并禁用编辑、完成和删除；跨页面刷新不会让当前关联任务从计时页消失。
- 点击任务表空白区域后选择和当前索引被清除，所有依赖任务选择的操作按钮立即禁用。
- 双击优先建议后切换到专注页，并自动选中对应任务。
- 专注暂停、继续、自然结束和提前终止均符合按钮状态设计。
- 计时空闲提示统一恢复为“准备开始”，切换计时类型不会留下过期提示。
- 不同任务自动使用各自方案，临时自定义方案不覆盖已保存方案。
- 内置预设不能修改或删除；复制后可以保存为用户方案。
- 自定义方案所有字段只有点击“确定”后才整体生效，确认后可命名保存，默认名称自动避开重名，空白区域可退出输入状态；编辑区无重复标题且按钮边框完整。
- 专注方案表支持全列排序，并默认按“默认、系统默认、系统预设、用户自定义”排列。
- 方案表始终占用 5 行高度；未点击表格时滚轮继续控制外层设置页，点击后由表格消费滚轮，滚到边界也不带动外层页面。
- 方案表选中行后可通过卡片或页面空白取消选择；计时页方案控件点击空白退出焦点但保留当前方案。
- 终止提示显示约 4 秒后自动回到准备状态，不长期占用中央状态栏。
- 休息终止不计入专注统计；专注记录精确显示到秒。
- 修改项目或分类颜色后，各相关页面同步使用新颜色。
- 最近 10 条记录完整显示、无内层滚动条，并支持全列排序。
- 分类和项目饼图在相邻小扇区下仍能错开标签，不出现文字重叠。
- 最小化后保留在任务栏；关闭后隐藏到托盘；托盘菜单可以真正退出。
- 托盘悬停信息随计时实时显示任务、阶段、暂停状态和剩余时间，专注与休息使用一致的任务字段。
- 原窗口最小化或隐藏后再次启动程序，只恢复原窗口，不产生第二个主界面。
- 原版系统提示音、内置提示音与自定义声音均可试听；可完整播放或限时平滑淡出，新提醒会先淡出旧声音，恢复默认后清理无用托管副本。
- 声音下拉框仅在获得焦点后响应滚轮，完整播放时最长播放限制显示为明确禁用状态。
- 数据库备份能够通过完整性检查；恢复不会在打开数据库时直接覆盖文件。

## 6. 验收标准

版本达到公开发布标准，需要同时满足：

1. Release 配置成功构建，无编译错误。
2. 12 个 CTest 测试目标全部通过。
3. 双进程启动验证中，第一个实例保持运行，第二个实例正常退出并发出恢复请求。
4. `git diff --check` 检查不产生空白错误。
5. README、用户指南、项目计划和架构说明与程序版本一致。
6. `windeployqt` 打包后的目录可以脱离 Qt Creator 启动。

## 7. 风险与控制

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 关闭窗口被误认为退出 | 计时仍在后台运行 | 托盘提醒、设置开关和明确的“退出”菜单 |
| 重复启动多个进程 | 状态混乱或数据库竞争 | 文件锁判定主实例，本地 IPC 唤醒原窗口 |
| 界面卡顿造成计时误差 | 专注记录不准确 | 使用墙上时钟差值计算剩余时间 |
| 自定义声音持续占盘 | 用户数据目录膨胀 | 只保留当前引用的托管声音副本 |
| 单一节奏不适合所有任务 | 用户频繁修改设置 | 多方案与任务默认绑定，保留本次临时调整 |
| 数据库恢复损坏数据 | 用户数据丢失 | 完整性检查、必需表检查、自动备份和下次启动替换 |
| 仅靠颜色表达状态 | 颜色识别困难 | 同时保留状态文字、星级和推荐分数值 |

## 8. 发布与维护流程

每个正式版本按以下流程维护：

1. 在独立分支完成新功能或问题修复，并同步更新相关文档。
2. 执行 Release 构建、全部 CTest 测试和关键人工验收场景。
3. 检查数据库兼容性、升级影响和用户数据安全。
4. 更新应用版本号、变更说明和 Windows 打包脚本。
5. 合并到 `main` 后创建对应 Git 标签，并生成可分发的 ZIP 发布包。

用户发现问题时，建议在 GitHub Issue 中提供应用版本、Windows 版本、复现步骤、
预期结果和实际结果。若问题涉及个人任务或数据库，请先移除隐私数据再上传附件。
